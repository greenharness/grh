## Context

greenrack 7.0.0 is on npm (t06). Its package `@greenharness/greenrack-cli@7`
already ships the renamed Claude side: the manifest names the MCP server
`greenrack`, the skill is `greenrack-mockup`, the `design-system-lookup` agent
uses `mcp__greenrack__greenrack_lookup`, and the `session_context` and `doctor`
guards match both scopes. What is left is grh's catalog, which detects only
`dep:@duro-app/`, and this machine, which still runs the 6.x install: the
`duro-ds` MCP, `~/.claude/skills/duro-mockup`, the old agent file, and an old
SessionStart guard in `~/.claude/settings.json` (and its chezmoi template).
t08 and t08b wait on this ticket, so detection on both scopes must be live
before any app is swept.

Found while orienting:
- **The skills repo needs no change.** `greenharness/skills` names only the
  generic agent contract `design-system-lookup` (plan-review step 2), and has
  no other DS reference. It is not released in this ticket.
- grh's `when` list is an AND, so "either scope" means two recommend rules.
- grh prints the SessionStart block and never writes it (`src/extension.rs:134`).
  The guard in settings.json was placed by hand, so it is changed by hand,
  in settings.json and `dot_claude/settings.json.tmpl` (no chezmoi drift today).
- The grh receipt's `ext:design` has 32 steps, including a **backup of a
  pre-grh `skills/duro-mockup/SKILL.md`**. Uninstall restores that backup, so
  the old skill comes back after uninstall and must be removed by hand.
- Out of scope: the ADR bodies and `aval.pack` (accepted records, generated);
  greenbelay's vendored `decisions.pack` (regenerated by its own sweep); app
  `.mcp.json` `duro-ds` entries (t08/t08b); dropping old-scope detection (t13).
